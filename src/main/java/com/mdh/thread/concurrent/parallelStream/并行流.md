# 并行流
~~~
list.parallelStream()

~~~

## 原理
~~~
parallelStream 的强大能力源于其底层的 Fork/Join 框架

1.拆分 (Fork)：将你的大数据集（任务）递归地分割成许多更小的子任务。
2.并行执行：利用一个名为 ForkJoinPool.commonPool() 的公共线程池来并发执行这些子任务。这个公共线程池的线程数量默认等于你机器的 CPU 核心数。
3.合并 (Join)：在所有子任务执行完毕后，将它们的处理结果汇总，得到最终结果。


~~~

## 线程安全问题
~~~
parallelStream 是多线程执行的，因此在流操作中修改共享变量是极度危险的。

// 错误示范：线程不安全
List<Integer> unsafeList = new ArrayList<>();
IntStream.range(0, 1000).parallel().forEach(unsafeList::add);
// 最终 unsafeList 的大小很可能小于 1000，因为 ArrayList 不是线程安全的

// 正确做法：使用无状态的归约操作
int safeSum = numbers.parallelStream()
                     .mapToInt(n -> n)
                     .sum(); // sum() 方法是线程安全的
~~~

## 顺序不确定性
~~~
并行处理会打乱元素的处理顺序。如果你需要保持顺序，必须使用 forEachOrdered，但这会牺牲一部分并行性能。

/ 输出顺序是随机的
numbers.parallelStream().forEach(System.out::println);

// 保持原始顺序，但性能会下降
numbers.parallelStream().forEachOrdered(System.out::println);
~~~

## 数据源的性能影响
~~~
parallelStream 的性能高度依赖于数据源能否被高效地拆分。
高效：ArrayList、数组。它们支持随机访问，可以快速地进行二分拆分。
低效：LinkedList、TreeSet。拆分它们需要遍历，成本很高，可能导致并行流比串行流更慢。
~~~

| 适用场景 | 不适用场景 |
| :--- | :--- |
| 数据量大 (如百万级以上) | 数据量小 (拆分合并的开销大于收益) |
| 计算密集型任务 (如复杂数学运算) | IO 密集型任务 (如读写文件、网络请求) |
| 不关心处理顺序 | 需要严格顺序执行 |
| CPU 资源充足 | CPU 已满载或 Web 高并发环境 (会占用公共线程池) |
