# 三色标记
~~~

https://blog.csdn.net/oJieSi/article/details/134758659

三色标记（Tri-color Marking） 是并发垃圾收集器（如 G1、CMS、ZGC）实现并发标记的核心抽象模型。
它通过将对象标记为三种颜色，来描述对象在垃圾回收过程中的状态，从而解决“用户线程与 GC 线程同时运行”带来的数据一致性问题。
~~~

## 
~~~
白色
    1- 在标记开始时，堆内存中的对象都是白色的。
    2- 在标记结束时，仍然是白色的对象，将会被视为已死的对象而被清除。
        
灰色
     灰色是由白色标记成为灰色，表示该对象Obj是根可达对象（存活的对象，不会被清理）,但Obj的所有引用的对象还没被垃圾收集器访问；
     灰色是一个过渡色，最终都会被标记为黑色。
     
黑色
    黑色是由灰色标记成为黑色，表示该对象Obj以及Obj的所有下级引用对象都已经被垃圾收集器访问并标记，Obj不会被垃圾收集器再次访问以查看是否有引用对象；
    此时Obj是黑色（存活的对象，不会被清理），Obj的所有引用的对象被标记为灰色。
    
    
总结：
三种颜色是递进的，最初所有对象颜色都是白色，对象Obj被根对象引用，当Obj被垃圾收集器访问后会被标记为灰色，当Obj的所有属性被访问标记（白色-->灰色）后Obj会被标记为黑色。
~~~

## 三色标记算法因为什么而出现
~~~
三色标记出现前，垃圾回收使用的算法是标记-清除算法，该算法显著特点就是整个垃圾回收周期中，用户的所有线程都会停止，也就是STW（stop the world，整个用户线程完全停止运行），非常不友好。

三色标记算法优化了标记-清除算法的STW，将一个相对大的STW分解成多个小的STW，做到了用户线程和垃圾回收的并发处理（这里并发也并非绝对并发，毕竟还存在少量的STW），减少了垃圾回收过程中STW的时间。
~~~

## 三色标记算法的漏洞
~~~
多标：多余标记，应该回收的对象让它存活了，概括让对象多存活一会，多标会产生浮动垃圾。
    解决：浮动垃圾对系统影响不大，无需干预，因为下次垃圾回收周期会把它们清除掉。
    黑色断开灰色


漏标：遗漏/忘记标记，应该存活的对象，被回收了，概括为忘记让对象存活了
     漏标问题的发生必须满足两个充要条件：
        1，至少有一个黑色对象新增了对白色对象的引用
        2，所有灰色对象指向该白色对象的引用都断开了

解决：
    1.CMS垃圾收集器使用增量更新方案。增量更新破坏了第一个条件（黑（黑->白的黑节点）->灰 重新标记）
        原本黑色对象指向白色对象，会把黑色记录下来，在重新标记阶段，黑色会标记成灰色，然后在以灰色为根节点，扫描整个引用链，白色对象依次会被标记为灰色，黑色
        缺点：会重新扫描以黑色对象D为根节点的整个引用链，会浪费多一点时间
        
    2.G1垃圾收集器使用原始快照方案。原始快照破坏了第二个条件（白（黑->白的白节点）->灰 当做根可达节点）
        灰色对象断开的白色对象，会被记录下来，在最终标记阶段，会把白色对象标记为灰色，然后以这个灰色为根节点，扫描整个引用链，如此以来原来白的对象会被依次标记为灰色，黑色
        缺点：如果没有黑色对象指向白色对象，白色对象会变成浮动垃圾，等下次GC回收
        
        
~~~
