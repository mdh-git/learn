# ZGC

~~~
https://blog.csdn.net/CrankZ/article/details/86009279

https://xie.infoq.cn/article/544d9e5586c702f4efa9a12b9

传统垃圾回收器 都是把对象的引用放在对象头中，对象头MarkWord记录GC状态
~~~

## ZGC 的设计目标
~~~
毫秒级的低延迟收集器
使用于 TB 级别的堆内存管理；
最大 GC Pause 不高于 10ms；
最大的吞吐率（Throughput）损耗不高于 15%；

关键点：GC Pause 不会随着 堆大小的增加 而增大。
~~~


## ZGC 中关键技术
~~~
加载屏障（Load barriers）技术；
有色对象指针（Colored pointers）
单一分代内存管理（这一点很有意思）
基于区域的内存管理；
部分内存压缩；
即时内存复用。
~~~

## 并行化处理阶段
~~~
标记(Marking);
重定位（Relocation）/压缩（Compaction）；
重新分配集的选择（Relocation set selection）；
引用处理（Reference processing）；
弱引用的清理（WeakRefs Cleaning）;
字符串常量池（String Table）和符号表（Symbol Table）的清理；
类卸载（Class unloading）。
~~~

## 核心分区  JDK21引入了分代概念
~~~
Large Page(大页面):最小单位是2MB(Linux默认)，由操作系统分配，减少内存碎片，提升回收效率。
Young Generation:存储短期存活对象，分为Eden和Surnvivor区，回收频率高、开销低(分代ZGC核心优化)。
Old Generation:存储长期存活对象，回收频率低，依赖并发标记·重分配流程，停顿时间极短。
~~~

## 关键特性
~~~
堆大小固定:由-XX:zHeapize配置(替代-Xns/-Xnx)，避免动态调整开销。
着色指针技术:通过指针标记对象状态(如存活、待回收)，无需额外维护对象头信息。
无Humongous区域:大对象直接存储在普通大页面中，无需单独划分区域，简化回收逻辑。
~~~

## 两者核心差异对比 (堆结构层面)
~~~
特性	                    G1收集器	                                                ZGC 收集器 (分代模式)
最小存储单位	         Region (1MB-32MB, 可配置)	                          Large Page (默认2MB, 操作系统级)
分区逻辑	             逻辑分区 (Eden/S0/S1/ Old/ Humongous)	              物理分代 (年轻代/老年代)+大页面
堆大小调整	         支持动态扩容/缩容 (-Xms/-Xmx)	                          固定大小 (-XX:ZHeapSize)
大对象处理	         单独划分 Humongous Region	                          直接存储在普通大页面，无特殊分区
核心优势	             平衡延迟与吞吐量，适配中小堆 (4G-32G)	                  毫秒级停顿，支持超大堆 (TB级)
~~~

## ZGC参数这是
~~~
-X:+UseZGC -Xx:ZHeapsize-8g -X:ZGenerationaltrue

-Xx:ZHeapsize=8g
    ·核心作用:固定ZGC的堆总大小为8G(不可动态扩容/缩容)
    ·设计目的:避免堆大小动态调整的开销，让ZGC更精准控制内存分区(大页面)，提升回收效率
    ·注意:不同于-Xms/-Xnx(最小/最大堆)，ZHeapSize是固定值，设置后-Xms/-Xmx失效。
    
2.-Xx:ZGenerational=true
    ·核心作用:启用分代ZGC(DK21+新增特性)。
    ·核心优化:将堆分为年轻代和老年代，年轻代对象回收更频繁、开销更低，老年代回收聚焦长生命周期对象，整体性能比非分代ZGC提升10%-30%(尤其对象创建频繁的场景)。
~~~


## 着色指针与多重映射
~~~
ZGC 使用了一种称为“着色指针（Colored Pointers，又称染色指针）”的技术，它将对象指针的高位用于存储额外的信息，
这些额外的信息可以用于标记对象的状态，进而帮助 ZGC 实现高效的并发垃圾回收。

着色指针的高位包含了 20 位的元数据，这 20 位元数据用于存储对象的标记信息。
目前，ZGC 中使用了其中的 4 位，剩余的 16 位保留用于未来的扩展。这 4 位的作用如下：

Marked0 & Marked1：这两位表示对象是否已被 GC 标记，以及是在哪个周期标记。ZGC 在每个 GC 周期中交替使用这两位，以确定对象是在上个周期亦或当前周期被标记。
Remapped：该位表示指针是否已经进行了重映射，即指针不再指向迁移集合（Relocation Set）中的对象。
Finalizable：该位表示对象是否仅通过 finalizer 可达。需要注意的是，JDK 18 中的 JEP 421 已经将 finalization 标记为过时，并将在未来的版本中移除。
~~~

## 主要流程
~~~
最开始都为Remapped 都为1

1.初始标记（STW 时间很短 1ms  跟堆的大小没有关系）
    只标记从GCRoots可达的对象，Marked0 位置修改为1，Remapped 修改为0  指针颜色发生变化
2.并发标记（三色标记）
    剩余对象标识,为了解决三色标记中漏标的问题，遇到 读引用的代码，增加读屏障（Load barriers）  剩余对象 Marked0 位置修改为1，Remapped 修改为0  指针颜色发生变化
3.再次标记（STW 时间很短 1ms ）
    处理三色标记漏标的问题
4.并发迁移准备
    进行分区中筛选（有垃圾的，有对象） 进行选择性的回收， 
    检查各区域发现，区域 1 与区域 2 存在需要回收的对象，将它们加入迁移集合。
    并为所有迁移集合中的区域创建转发表（Forward Table）
5.初始转移（STW 时间很短 1ms ）
    与GCRoots相连的对象进行转移  增加转发表指针信息
    Marked0 位置修改为0，Remapped 修改为1 指针颜色发生改变  
6.并发转移
    剩余对象转移 记录老的和新的地址关系
    
    
问题1：在并发转移阶段程序读数据已经在转发表中的数据
    ZGC通过度读屏障，会完成指针的修正（删除该条记录）
    
问题2：迁移后的任意时间用户线程加载对象
    会触发读屏障，（指针实际颜色 Marked0 与期望颜色 Remapped 不符，是“坏的”）。在读屏障中，会基于转发表，将对象 7 的地址重映射对象 7'。

问题3:下一次GC标记阶段重映射所有未被用户线程加载过的对象
    在下一次 GC 的标记阶段，会使用 Marked1 标记出所有存活对象。
    对象的实际颜色 Marked0 与期望颜色 Remapped 不符,会基于转发表,地址重映射
    
下一次 GC 迁移准备阶段清理转发表
    

 转发表
指针   old地址     new地址
 A     000001     111001
 B     000011     111 011
~~~
