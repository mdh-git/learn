# G1

## 核心架构：Region（区域）
~~~
低延迟、高吞吐量


G1 的核心革新在于打破了物理分代，采用了“逻辑分代、物理分区”的架构。

G1 将堆内存划分为多个大小相等的独立区域（Region），每个 Region 大小通常在 1MB ~ 32MB 之间（根据堆大小自动计算，是 2的n次方）。

逻辑角色 vs 物理存在
虽然物理上都是 Region，但在逻辑上，它们扮演不同的角色：
1.Eden 区：新对象分配地。由多个 Eden Region 组成。 （占用50%-60%）
2.Survivor 区：Minor GC 后存活对象的暂存地。由多个 Survivor Region 组成。
3.Old 区：长期存活对象。由多个 Old Region 组成。
4.Humongous 区：专门存放超大对象。
    判定标准：对象大小 > Region 容量的 50%。
    机制：大对象会占用连续的多个 Humongous Region。
    回收：Humongous 对象被视为老年代对象，但 G1 会在 Young GC 时顺便回收那些不再被引用的 Humongous 对象（这是 G1 优于 CMS 的地方之一）。
    
    
动态变化：在一次 GC 前后，Region 的角色可以动态改变。例如，一次 GC 后，原本的 Eden Region 可能被清空并转变为 Old Region 供下次使用。
~~~

## Young GC (YGC)
~~~
触发：Eden 区满。
行为：
    1.暂停应用线程 (STW)。
    2.将 Eden 和 Survivor 中的存活对象复制到空的 Survivor Region或Old Region。
    3.清空所有 Eden 和旧的 Survivor Region。
    4.特别优化：同时检查是否有不再被引用的 Humongous 对象，如果有，直接回收（无需等到 Mixed GC）。
特点：速度极快，停顿时间可控。
~~~

## Mixed GC (混合回收) —— G1 的灵魂
~~~
这是 G1 实现“可预测停顿”的关键。它不是 Full GC，而是部分老年代回收。

触发条件：当老年代占用率达到阈值 -XX:InitiatingHeapOccupancyPercent (默认 45%) 时触发。
行为：
    1.并发标记：后台线程遍历对象图，标记存活对象（不 STW）。
    2.并发标记之后，会有重新标记阶段解决漏标问题，此时需要暂停用户线程（STW）
    3.选择集合 (Collection Set, CSet)：G1 算法计算哪些 Region 中垃圾最多（即回收收益最大）。
    4.执行回收：在 STW 阶段，不仅回收新生代，还回收选定的那部分“垃圾最多”的老年代 Region。
名字由来：Garbage-First 意为“优先回收垃圾最多的区域”。
~~~

## Full GC
~~~
触发：当 Mixed GC 无法跟上对象分配速度，或者堆内存完全耗尽时。
行为：退化为单线程的“标记 - 整理”算法（类似 Serial Old），会扫描整个堆。
影响：长时间 STW，性能极差。
目标：调优 G1 的核心就是避免 Full GC 的发生。
~~~



## 总结
~~~
应用于新生代和老年代，在JDK9之后默认使用G1
划分成多个区域，每个区域都可以充当eden,survivor,old,humongous，其中humongous专为大对象准备
采用复制算法
响应时间与吞吐量兼顾
分成三个阶段:新生代回收(stw)、并发标记(重新标记stw)、混合收集
如果并发失败(即回收速度赶不上创建新对象速度)，会触发Full GC
~~~
