# 长轮询和长连接
~~~
长轮询 (Long Polling)：是一种应用层策略，目的是模拟实时推送（解决“如何高效获取最新数据”的问题）。Nacos 配置刷新用的就是这个。
长连接 (Long Connection / Keep-Alive)：是一种传输层/网络层机制，目的是减少握手开销（解决“如何避免频繁建立/断开 TCP 连接”的问题）。
~~~

## Nacos的配置推送场景
~~~
长轮询是建立在长连接之上的

1.底层 (TCP)：客户端与 Nacos Server 之间建立了 HTTP 长连接 (Keep-Alive)。这意味着客户端发起长轮询请求时，不需要每次都进行 TCP 三次握手，速度更快。
2.上层 (业务)：客户端通过这个长连接发送了一个 长轮询 HTTP 请求。
3.过程：
    Nacos Server 收到请求，挂起该请求（占用一个工作线程或协程）。
    此时，底层的 TCP 连接依然是通的（心跳保活），但没有数据传输。
    一旦配置变更，Server 通过这个已有的连接返回响应。
    请求结束，HTTP 事务完成。
    客户端紧接着通过同一个 TCP 长连接发起下一次长轮询请求。

关系总结：
    长连接是“路”，修好了就不拆，方便车随时跑。
    长轮询是“车的运行规则”，车开出去后，如果没有货物（数据变更），就在原地等着，直到有货物或者等太久才回来，然后马上再派一辆车出去（复用同一条路）。

~~~
