事务:部分支持事务（不强一致性）（不支持回滚的）
可以一次执行多个命令，本质是一组命令的集合。
一个事务中的所有命令都会序列化，按顺序地串行化执行而不会被其它命令插入，不许加塞

一个队列中，一次性、顺序性、排他性的执行一系列命令

DISCARD:取消事务,放弃执行事务内的所有命令
EXEC:执行所有事物内的命令
MULTI:标记一个事务块的开始
UNWATCH:取消WATCH命令对所有key的监视
WATCH key[key ...]  监视一个(或多个)key，如果在事务执行之前这个(或这些)key 被其他命令所改动，那么事务将被打断


Redis 事务为什么不支持回滚？
    Redis 的事务不支持回滚，但是执行的命令有语法错误，Redis 会执行失败，这些问题可以从程序层面捕获并解决。
    但是如果出现其他问题，则依然会继续执行余下的命令。这样做的原因是因为回滚需要增加很多工作，而不支持回滚则可以保持简单、快速的特性。

## 监控watch
~~~
watch 命令用于客户端并发情况下，为事务提供一个乐观锁（CAS，Check And Set），也就是可以用 watch 命令来监控一个或多个变量，如果在事务的过程中，某个监控项被修改了，那么整个事务就会终止执行。
watch 基本语法如下：

watch key [key ...]
~~~


## Pipeline的原子假象
~~~
Pipeline打包发送不是原子操作。

Pipeline只是减少RTT(往返时间)。在Redis服务器，这些命令可能被其他客户端的命令插队。

命令:Pipe A1    命令:Pipe A2  命令:Clent B1  命令:Pipe A3

Pipeline不具备原子性，不具备互斥性

~~~

## redis事务
~~~
MULTI BLOCK
Redis事务不满足ACID中的A(原子性:要么全做全么全都不做)

中间命令报错(如:类型错误)，后续的命令依然会执行，切无法回滚
~~~

~~~


## Lua脚本
~~~
Redis会将整个Lua脚本作为一个整体，执行期间绝对不会被其他线程命令插入

Lua脚本要控制运行的时间，redis是单线程，需要等待Lua脚本执行完成。不能通过SCRIPT KILL 中断当前的脚本
~~~


~~~
批量操作  无原子性要求，可以使用Pipeline
逻辑简单  可以使用lua脚本(必须短平快)
业务复杂  分布式锁/消息队列
~~~
