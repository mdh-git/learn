# 跳跃表
~~~
Redis中的跳跃表(SkipList)是一种有序数据结构，它通过维护多级索引来实现高效査找、插入和删除操作，在Redis中主要用于实现有序集合(Sorted Set)和集群节点内部数据结构。
~~~

## 特点
~~~
1.多层链表结构
    每个节点包含多个前进指针(forward pointers)，分别指向不同层的后继节点。
    节点层数通过幂次定律(概率随机化)确定，范围在1到32(Redis5.0后为64)之间。
~~~

## 节点构成
~~~
typedef struct zskiplistNode {
    robj *obj;                         //成员对象(有序集合中存储的元素)
    double score;                      //分值(排序依据)
    struct zskiplistNode *backward;    //后退指针(用于反向遍历)
    
    struct zskiplistLevel{
        struct zskiplistNode *forward;  //前进指针
        unsigned int span;              //跨度(到下一节点的距离)
        }level[];
} zskiplistNode;
~~~

## 整体结构
~~~
typedef struct zskiplist {
    struct zskiplistNode *header,*tail; // 头尾指针
    unsigned long length;               //节点数量
    int level;                          //当前最大层数
} zskiplist;
~~~

## 核心优势
~~~
1.查询效率接近平衡树
    平均时间复杂度 O(log N)，最坏情况 O(N)。
    通过多级索引实现“跳跃式”查找，无需像平衡树频繁旋转。
2.范围查询高效
    结合后退指钎和跨度(span)属性，支持快速范围操作(如ZRANGE)。
    可直接定位区间起点，顺序遍历即可，无需回溯。
3.实现简单且稳定
    相比红黑树等平衡树，代码更简洁，调试和维护成本低。
    插入/删除只需局部调整相邻节点指针，避免复杂再平衡。
4.内存使用灵活
    索引层数随机生成，无需绝对平衡，
    平均每个节点仅需约1.33层指针(理论值)，空间效率较高。
5.天然有序性
    节点按分值升序排列，相同分值按成员字典序存储，支持双向遍历。
~~~


## Redis中的应用场景
~~~
1.有序集合(Sorted Set)
    当元素数量较多或成员较长时，Redis默认使用跳跃表实现(zset-max-ziplist-entries和zset-max-ziplist-value 值控制)。
2.集群节点内部维护
    用于管理槽位映射等需要快速查找的场景。
~~~

## 性能示例
~~~
假设有序集合含 100000  个元素:
    查询单个元素:跳跃表平均约20次比较
    范围查询前100个元素:先O(log N)定位起点，再线性遍历100步
~~~

## 总结
~~~
Redis选择跳跃表的核心原因是:在保证近似对数时间复杂度查询的同时，获得了更简单的实现、更高效的范围查询能力，以及更适合Redis场景的扩展性。
这种设计平衡了性能、可维护性和功能需求，体现了Redis“简单高效”的设计哲学。
~~~
