## 预审流程
~~~
1.上传图纸，保存到Minio中（保留图纸的url地址）
2.上传成功后开始预审

通过责任链方式、创建五个方法，按照设置的责任链顺序执行
预审流程：
1.C++导图（把DWG文件解析成图源）
2.图框、图签、计算书坐标检测（找图框，图签（整个最右边一列）（子项名称））
3.图源数统计、拆分图源（所有图源拆到图框、md5）
4.CV图签精准识别检测（CV去精准识别图签信息（图签只有左下角），CV会去除相关图源）
5.多模态识别（截图，大模型识别图片上的信息）（图源里面的文字、多模态返回的文字比较  动态规划修改文字）

主要存储 图源、图签、图框信息

~~~

## 审图流程
~~~
1.获取CV识图数据，数据合并
2.二次识图
3.规范审查
4.报告、数据展示



// 整个审图
@RefreshScope
public class StartReviewHandler{
    startReview 开始审图
    doSteps 执行步骤
    stepComplete 合并结果
}


定义 abstract class ReviewSteps<R, T>
abstract public List<TaskStepsLog> createTaskSteps(ReviewDrawsDTO reviewDrawsParam, TaskLog taskLog);  创建step
abstract public R doHandler(StepsArg stepsArg);                                                        执行step
abstract T stepResultHandler(List<TaskStepsLog> taskStepsLogs, ReviewDrawsDTO reviewMsg)               获取结果

在容器初始化的会创建好所有专业的step步骤，在每个step上面的都会有@Component
在审图会选用某个专业获取执行对应的ReviewSteps


审图流程
inspector_request_review_topic
1.消费inspector发送消息，开启审图，进度0.1
2.初始化审图步骤，获取专业审图步骤，(结构为例，先创建层高表的step、创建每个图框的step)
3.执行创建的步骤（执行创建的审图任务），修改进度0.2，发送消息inspector


steps_complete_topic
4.处理审图步骤完成处理，合并结果，发送进度：0.3
    redis加锁保证，保证一个任务只会执行一次
    合并结果中，分专业处理不同的逻辑
        CV返回的数据转换显示，合并各个图框数据，转成json存储
        进行二次识图，按照流程图开发业务逻辑
        存储二次识图的结果（Fury文件）
        进行计算书的比对
5.各个专业二次识图结果转化  进度：0.4
6.规范审查完成  进度:1
    获取配置的流程图
        1.进行取值(流程图上配置的变量)
        2.筛选结果map key=  pathId+varId+objId
        3.进行分组
        4.提取变量进行判断,
